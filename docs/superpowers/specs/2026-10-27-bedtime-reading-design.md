# 睡前朗读

在现有 `/read` 上读一整本 txt。书架、拆章、跨次书签、逐句高亮、暂停，以及播放满设定时长后自动停下。短稿朗读保持原样。

## 范围

做：

- `~/.config/dock-hub/books/` 里的 `.txt` 作为书架
- 用 `zh-chapter-splitter` 拆章，进度记「哪本书、第几个字」
- 从书签逐段送给现有书桌喇叭，页面标出当前句
- 播放计时，默认 30 分钟，到点停下并留下书签
- 浏览器接口与 `docs/lan-protocol.md` 的说明

不做：

- 不自动开读。打开页面只载入上次那本并滚到书签
- 不把整章塞进八千字短稿任务，不生成故事的 WAV
- 不另起阅读器进程，不拷贝 `zh-chapter-splitter` 的源码
- 没有删除按钮。文件从 `books/` 拿走后，书架不再列出
- 不跳过作者说明和后记
- 不定时短稿。定时只作用于故事播放
- 安卓不调用这些接口
- Hub 重启后不接着念。书签和「定时多少分钟」还在，倒计时本身不保留

## 书架与正文

目录与 `reads/` 并列：`~/.config/dock-hub/books/`。只看这一层的 `*.txt`，不进子目录。`progress.json` 不是书。

书的 id 就是文件名。上传和路径解析只接受单个文件名，以 `.txt` 结尾，不含 `/`、`\` 或 `..`。解析后的路径必须仍在 `books/` 里。展示名是去掉 `.txt` 的文件名。

导入与 `POST /v1/companion/books` 都是把字节写入这个目录。请求体是原文，文件名在 `X-Filename`（百分号编码的 UTF-8）。超过 32MB 拒绝。同名覆盖。覆盖后若原书签仍落在新正文长度内，书签保留，否则收到最后一个字。

打开一本书时才解码并拆章。解码、清洗、拆章都调用 `zh-chapter-splitter`（`decode_bytes`、`clean_text`、`split_chapters_with_report`）。结果只留在内存，键是路径、大小和 mtime。文件变了就重拆。不把拆章结果另存成一份正文。

书签偏移指的是各章 `content` 按顺序拼成的那条字符串，章与章之间不另加字符。每一章有 `start` 和 `end`（`end` 不含）。没有章节标题时，整篇是一章，标题用展示名。卷名放在章对象的 `volume` 上，目录里换卷时标一行，不单独做一层导航。章标题显示在目录和页眉，不单独再念一遍；正文里本来有的字照念。`is_author_note` 的章照常出现在目录里并照常念。

`books/progress.json`：

```json
{
  "current_id": "雾海.txt",
  "timer_min": 30,
  "books": {
    "雾海.txt": { "offset": 12034, "updated_at": 1761570000 }
  }
}
```

`timer_min` 是偏好，不是剩余秒数。缺文件、坏 JSON、缺字段时：`current_id` 为 `null`，`timer_min` 为 30，没有任何书签。不自动挑第一本。已不在书架上的书签项下次保存时丢掉。

## 播放

故事播放在 `dock_hub/books.py` 的一条线程里。同时只有一个故事。后一次播放或暂停覆盖前一次。`companion.py` 只提供「送一句」和「停喇叭」。短稿任务的队列、八千字上限、生成 WAV 不改。

从书签取当前章剩余正文，用现有的 `chunk_read_text` 和 `pack_read_chunks` 切段。送出的一段必须是拼合正文里的连续切片。每次只送一段。送出之前就把书签写成这一段的 `sentence_start` 并落盘。高亮就是这片切片，长度等于这段文本的字数。纯标点、空段直接跳过，书签落在切片第一个字上，避免停在原地。

下一段要等 `estimate_read_seconds` 给出的秒数再送，也就是现有的大约四字一秒。测试用注入的时钟，不真的睡那么久。等待可以被暂停、跳章和到点打断。这样喇叭里大约只压着刚送出的那一段，半小时对齐的是在听的时间。等待结束、准备下一段时，读指针才移到这段末尾；中途停下则书签仍在段首，下次把这一句再读一遍。

本章 `content` 读完后，从下一章 `start` 继续，中间不停。没有下一章时停下，`stopped_by` 为 `end`，书签留在正文末尾，倒计时清掉。已经在末尾时再按播放，从第 0 字重新开始。

暂停和页头「停止」是同一条路径：停喇叭（缓冲清掉），书签留在刚送出的那一段开头，`stopped_by` 为 `user`。到点也走停喇叭和留书签，`stopped_by` 为 `timer`。

故事在读时去播短稿：先按暂停留下书签，再开始短稿。短稿在读时去播故事：先停掉短稿（现有的停止），再开始故事。

Hub 进程退出则喇叭与线程都没了。下次打开不自动出声。

## 定时

只在故事播放时计时。默认 30 分钟。可选 关、15、30、45、60，对应 `timer_min` 的 `0`、`15`、`30`、`45`、`60`。其它数字拒绝。

同时最多一段倒计时。`timer_min` 为 0 时没有倒计时。播放开始时：已经有正在走或被冻住的剩余秒，就接着用它，不重新给满；否则给满一个 `timer_min`。因此暂停后再播放会接着倒数。跳到别的章、换一本正在听的书，也接着用剩下的时间。到点或读完会把倒计时清掉，下一次播放才重新给满。到点不把偏好改回 0。

用户暂停会冻住剩余秒。把定时改成另一档时，剩余时间改成新的整段；正在读就从现在重算，暂停中就先记下，恢复播放后再倒数。改成关则清掉倒计时，朗读继续或保持暂停。

到点检查发生在「送下一段之前」和「两段之间的等待」里。已经送出的那一段会被停喇叭清掉，书签仍在它的开头。

倒计时只在内存里。重启后播放是停的，偏好仍是上次选的分钟数。

## 页面

仍是 `GET /read`。左边默认是当前章的正文，不是整本放进文本框。打开页面请求书架和故事状态，载入 `current_id`，滚到书签。没有书时，左边是空书架和「导入」。

正文上方是书名、章名、`index + 1` / 总章数、全书百分比。当前段用一条高亮标出，并保持在视野里。高亮是 `sentence_start` 起的那一片连续正文；章没载入时先取那一章。

按钮：播放、暂停、上一章、下一章。正在读时，点目录里的章就是带着那一章的 `start` 去播放，倒计时不重置。没在读时只把书签放到那一章开头并显示正文，不出声。上一章、下一章同样。

定时放在这排按钮旁。选项是关、15 分钟、30 分钟、45 分钟、60 分钟。正在读时显示剩余分钟（不足一分钟显示剩余秒）。暂停时显示冻住的剩余时间。到点后状态行写「到时间了，已停下」。读完一本写「已读完」。

左下是「短稿」。点开仍是原来的文本框、播放、生成 WAV、自动下载和任务列表。右边在故事视图是目录：换卷时加一行卷名；拆章报告的 `problem_label` 非空时，目录上方静静显示这一句。短稿视图的右边仍是任务列表。

焦点在短稿文本框里时，原有快捷键不变。否则空格切换播放 / 暂停，Esc 暂停故事。

## 接口

与 `/read` 相同：本机免 Token，局域网要 Token。安卓不调用。

`GET /v1/companion/books`

```json
{
  "items": [
    { "id": "雾海.txt", "title": "雾海", "bytes": 1048576, "mtime": 1761570000 }
  ],
  "current_id": "雾海.txt",
  "timer_min": 30
}
```

列表不拆章。`current_id` 没有对应文件时为 `null`。

`POST /v1/companion/books`  
正文原样上传，`X-Filename` 为文件名。成功返回这本书的 id 和字节数，并把它设为 `current_id`。

`GET /v1/companion/books/{id}`

```json
{
  "id": "雾海.txt",
  "title": "雾海",
  "encoding": "gb18030",
  "chars": 800000,
  "bookmark": 12034,
  "chapters": [
    { "index": 0, "title": "第一章 雾", "volume": "卷一", "start": 0, "end": 4200 }
  ],
  "problem_label": ""
}
```

不返回正文。`index` 从 0 起。

`GET /v1/companion/books/{id}/chapter/{index}`

```json
{ "index": 0, "title": "第一章 雾", "text": "……", "start": 0, "end": 4200 }
```

`POST /v1/companion/books/{id}/play`  
正文可省略，或 `{"offset": 4200}`。省略则用书签；书签已在末尾则从 0 开始。已经在读时再次调用是跳转，倒计时按上一节接着用。返回与 `GET /v1/companion/story` 相同的对象。

`POST /v1/companion/books/{id}/pause`  
停喇叭并留下书签。返回同一个故事对象。

`POST /v1/companion/books/{id}/bookmark`  
`{"offset": 4200}`。没在读时移动书签并设为当前这本书，不出声，也不改倒计时。正在读时返回 400，跳转要走播放接口。偏移超出末尾时收到最后一个字。返回故事对象。

`POST /v1/companion/story/timer`  
`{"minutes": 30}`。写入偏好，并按上一节重置或清掉倒计时。返回故事对象。

`GET /v1/companion/story`

```json
{
  "playing": true,
  "book_id": "雾海.txt",
  "offset": 12034,
  "chapter": 3,
  "chapter_title": "第四章 岸",
  "sentence": "海雾又厚了一层。",
  "sentence_start": 12034,
  "chars": 800000,
  "chapters": 120,
  "timer_min": 30,
  "timer_remaining_sec": 1080,
  "stopped_by": null,
  "error": null
}
```

没在读时 `playing` 为 false，仍返回上次的书、书签和章，方便把页面画出来。定时关着、还没开始倒数、或倒计时已被到点 / 读完清掉时，`timer_remaining_sec` 为 `null`。用户暂停后仍返回冻住的剩余秒。`stopped_by` 取 `user`、`timer`、`end`、`error` 或 `null`。

页头「停止」仍走 `POST /v1/companion/stop`。故事正在读时，这次停止同时走故事暂停。

## 错误

沿用现有 `{"error": {"code", "message"}}`，`message` 用中文。

| 情况 | 结果 |
| --- | --- |
| 文件名带斜杠、空、不是 `.txt` | 400，拒绝写入 |
| 超过 32MB | 400 |
| 未知 id、章序号越界 | 404，没有这本书 / 没有这一章 |
| 文件打不开、解码失败 | 书架上仍有这条。打开或播放时 400，说明读不出 |
| 拆章抛错 | 整篇当作一章，标题用展示名 |
| 正文没有可读的字 | 播放 400，「没有可以读的字」 |
| `minutes` 不是 0、15、30、45、60 | 400 |
| 正在读时调用书签接口 | 400，跳转要走播放接口 |
| 读到一半喇叭失败 | 停下，书签留在最后一次成功送出的段首。没成功过就留在这次要读的位置。`stopped_by` 为 `error`，`error` 用短稿那类失败说明 |
| `progress.json` 损坏 | 当作没有书签，定时偏好回到 30 |
| 字偏移超出末尾 | 收到最后一个字 |

## 代码与依赖

- `hub/dock_hub/books.py`：书架、拆章缓存、书签、播放线程、定时
- `hub/dock_hub/companion.py`：交出逐句送喇叭和停止。短稿路径不改行为
- `hub/dock_hub/server.py`：上面的路由，鉴权与 `/read` 相同
- `hub/dock_hub/assets/read.html`：书架、正文、目录、定时、短稿
- `hub/pyproject.toml`：增加依赖 `zh-chapter-splitter`，实现时钉住所解析到的版本
- `docs/lan-protocol.md`：写下这些路由，并写明安卓不调用
- `hub/README.md`：在配置目录表加上 `books/`

## 测试

放在 `hub/tests/`，沿用现有 Hub 测试方式。短稿已有测试保持通过，并确认故事播放不会造出一条八千字短稿任务。

要覆盖：

- 非法文件名、超过 32MB 被拒绝；同名覆盖后，书签在新长度内则保留
- 没有「第×章」的文本变成一章；拆章异常时也变成一章
- 字偏移能算出章序号；超出末尾被收住
- 暂停落在当前段开头；读完一章会进入下一章；读完最后一章后再次播放从 0 开始
- 两段之间会等待 `estimate_read_seconds` 的秒数；用注入的时钟，等待中暂停会立刻返回
- 定时到点后 `stopped_by` 为 `timer`，书签在段首，偏好分钟数不变，倒计时被清掉；再播放才重新给满
- 暂停冻住剩余时间，恢复后继续减，而不是重新给满；跳章也不重新给满
- 播放中把 30 改成 15，剩余时间改为 15 分钟；改成 0 则 `timer_remaining_sec` 为 `null` 且朗读不因此停止
- 正在读时调用书签接口得到 400；没在读时跳章不出声
- 故事与短稿互相抢喇叭时，故事侧会留下书签
- 损坏的 `progress.json` 读成 `current_id: null`、`timer_min: 30`、没有书签
